# 親子成長指南：單頁完整構圖重設規格

## 目標

保留現有封面、原始文字與圖片，重新編排封面以下的內容。每個原始主題必須成為一個完整、集中且有明確視覺重點的畫面，不能再將同一頁的標題／圖片與詳細內容拆成兩個主畫面。

網站應同時達成：

1. 看起來像經過編輯設計的精品親子刊物，而不是套版卡片集合。
2. 訪客能快速理解每一頁要表達的單一重點。
3. 銷售動線自然累積信任，最後願意前往送禮頁或聯絡 LINE。
4. 桌機、平板與手機都保持清楚的閱讀層級。

## 不變範圍

- 現有封面視覺與主要構圖保留。
- 現有核准文字原則上不刪減、不改價、不改法律與服務資訊。
- 11 張本地圖片全部保留，包括 3 張家長真實回饋截圖。
- LINE、送禮頁、導航者、購買與退款頁的既有連結與業務邊界不變。
- 維持純 HTML／CSS、GitHub Pages 靜態網站。

## 核心排版原則

### 一個主題，一個完整構圖

桌機版中，每個主題必須在一個視窗高度附近完成主要敘事；不得為了版型把同一主題拆成「標題與圖片一段、內容卡片下一段」。

手機版不強迫所有資訊塞入一個實體螢幕，但同一主題必須維持在一個連續區塊內，背景、間距與視覺關係不能中斷。

### 圖片分級

圖片依功能使用不同尺寸，避免每張圖片都成為同等重量的大主視覺：

- **主視覺圖**：封面與結尾宇宙圖，可使用滿版或大幅裁切。
- **章節圖**：困惑、獨特孩子、製作流程、資料、成品、轉變等圖片，占桌機構圖約 35–45%。
- **證據圖**：3 張家長截圖，以清楚可讀為優先，放入緊密的證據展示區，不做裝飾性裁切。

### 文字層級

- 每個主題只能有一個主要標題。
- 標題下先放一句核心敘述，再放 3–4 個支撐重點。
- 內文最大行寬控制在易讀範圍，避免跨滿整頁。
- 大標只用於封面、章節主張與最後情緒收束；卡片標題採較小一致字級。
- 卡片不是預設容器。只有內容需要比較或分組時才使用卡片。

### 密度與留白

- 留白必須服務資訊層級，不能讓一行標題占用半個螢幕。
- 桌機章節高度由內容決定，但主要章節應控制在約 680–900px。
- 合併目前被拆開的主題段落，預期首頁總高度顯著縮短。
- 使用一致的 8px 間距系統；章節內部緊密、章節之間清楚。

## 首頁章節構圖

### 1. 封面

保留目前沉浸式星空封面，包括主要標題、簡述、兩個 CTA 與親子星空圖片。僅允許必要的細微響應式修正。

### 2. 家長困惑

合併目前的 `concerns` 與 `concerns-details`：

- 左側：主標題、四個困惑，以緊密的 2×2 重點排列。
- 右側：家庭困惑圖片。
- 結論「不是你沒耐心……」作為整頁底部的情緒收束。

圖片不得比全部文字內容更重；標題不能單獨占一個大區域。

### 3. 每個孩子都是獨特的

合併 `unique-child` 與 `unique-child-details`：

- 一側放親子圖片。
- 另一側放主張、導讀與三個價值。
- 三個價值採垂直編輯清單或緊密欄位，不再另開一屏卡片。

### 4. 我們怎麼做

- 流程四步與專業說明為主要內容。
- 探索圖片作為輔助視覺，尺寸小於文字區。
- 流程編號、標題與說明形成一條清楚的閱讀路徑。
- 圖片預留固有比例，避免懶載入時版面位移。

### 5. 需要哪些資料

合併 `required-data` 與 `required-data-details`：

- 主標題、四項資料、隱私說明與資料防護圖片同頁呈現。
- 四項資料採 2×2 簡潔資訊塊；隱私說明緊接在資訊塊下方。
- 圖片是信任輔助，不做超大人物主視覺。

### 6. 送禮承接

以短而有力的暖色帶承接產品理解與送禮意圖：

- 一句送禮主張。
- 一句不施壓的說明。
- 一個主要 CTA。

此區不得高於必要內容，不製造空洞大留白。

### 7. 你將得到什麼

合併 `deliverables` 與 `deliverables-details`：

- 指南預覽圖必須明確顯示為「成品預覽」。
- 標題、8 仟字 PDF 說明、四項內容與長期使用價值同頁完成。
- 桌機可採 40% 成品圖＋60%內容；四項內容使用緊密兩欄。
- 不再讓成品圖與四項內容各占一個畫面。

### 8. 價值與價格

- 保留完整比較表內容。
- 先用簡短主張說明「買到的是什麼」，再進入比較。
- 本指南欄位必須成為視覺焦點，但不能用過度飽和或誇張促銷效果。
- 桌機完整可讀；手機使用明確的橫向提示或改成可掃描的比較群組。

### 9. 指南帶來的轉變

合併 `transformation` 與 `transformation-details`：

- 閱讀圖片、三項轉變與家長引言同頁呈現。
- 三項轉變以垂直進程或三欄短敘述排列。
- 引言作為頁面收束，不另開下一屏。

### 10. 家長真實回饋

- 標題、來源說明與三張截圖形成一個完整證據區。
- 截圖保持原比例與清晰度。
- 桌機以一大兩小或等高錯落方式集中呈現；手機單欄連續排列。
- 不使用旋轉、過度陰影或裁切，以免降低真實感。

### 11. 結尾與行動

合併目前的 `closing-vision` 與 `closing`：

- 宇宙親子大圖、情緒主張、完整結語與兩個 CTA 在同一個結尾構圖完成。
- 深色背景延續封面，形成首尾呼應。
- CTA 必須在讀完結語後立即可見。

## 銷售動線

依 `ui-ux-pro-max` 的 storytelling 與 social-proof 建議，內容順序維持：

1. 情緒鉤子：看見孩子。
2. 問題共鳴：家長困惑。
3. 價值主張：個別化理解。
4. 專業方法：如何完成。
5. 低負擔與信任：資料與隱私。
6. 送禮想像：把理解送給家庭。
7. 產品具體化：實際得到什麼。
8. 價格合理性：價值比較。
9. 結果想像：帶來的轉變。
10. 社會證明：真實家長截圖。
11. 情緒收束與 CTA。

首頁不新增干擾性的浮動購買按鈕，不使用倒數、限量或假緊迫感。

## 響應式規則

### 桌機 1024px 以上

- 章節主要採雙欄，但文字／圖片比例依內容調整，不統一套用 50/50。
- 一個主題控制在一個視窗高度附近。
- 標題與內文不跨越過長行寬。

### 平板 768–1023px

- 雙欄可改為 45/55 或堆疊。
- 圖片高度不得超過文字內容兩倍。
- 2×2 資訊組維持兩欄。

### 手機 375–767px

- 每個主題維持單一連續 section。
- 先呈現標題與核心說明，再依語意放圖片或重點；不是所有章節都固定「文字先、圖片後」。
- 圖片最大高度與裁切依用途設定，避免連續出現多張滿屏大圖。
- 按鈕滿寬、文字至少 17px、觸控高度至少 52px。
- 不得有橫向頁面溢出。

## 驗收標準

- 封面以下不再存在只放標題與圖片、詳細內容另開下一段的主題。
- `concerns`、`unique-child`、`required-data`、`deliverables`、`transformation` 與 `closing` 各自只形成一個完整視覺章節。
- 桌機每個主題的標題、核心文字、圖片與重點在同一個章節內可見。
- 首頁總高度相較現況明顯縮短，且沒有因縮短而裁掉文字。
- 11 張圖片與所有核准文字仍存在。
- 375、768、1024、1440px 無橫向跑版。
- 懶載入圖片載入前後不造成明顯版面位移。
- 家長回饋截圖清晰、完整且可信。
- 主要 CTA 在封面、送禮承接與結尾各有清楚位置。
- 自動測試與瀏覽器視覺驗收全部通過後才推送 GitHub Pages。
