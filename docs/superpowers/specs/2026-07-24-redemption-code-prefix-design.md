# 兌換碼前綴與來源分類設計

## 目的

以兌換碼本身辨識發行來源，同時讓正式銷售與品牌贈送共用同一套兌換及指南製作流程。前綴只供營運分類，不影響收禮者取得的服務內容。

## 代碼格式

- 正式營運：`STAR-YYYY-XXXX`
- 品牌贈送：`GIFT-YYYY-XXXX`

其中：

- `YYYY` 是發行當年的四位西元年份，例如 `2026`。
- `XXXX` 是四位大寫英數亂碼。
- 亂碼排除容易混淆的 `I`、`O`、`0`、`1`。
- 每一組完整兌換碼都必須唯一，不得重複發行。

範例：

- 正式營運：`STAR-2026-A7K9`
- 品牌贈送：`GIFT-2026-M8Q3`

## 分類規則

### STAR

凡是由正式訂單產生的兌換碼都使用 `STAR`，包含：

- 顧客購買後自用。
- 顧客購買後轉送親友。
- 顧客一次購買多份後分別轉送。

分類依據是「兌換碼由正式訂單產生」，不是最後由誰使用。

### GIFT

由赫爾墨斯的小宇宙或星學會有限公司主動免費贈送、沒有對應付費訂單的兌換碼使用 `GIFT`，例如：

- 品牌致贈親友。
- 合作夥伴或特別活動贈禮。
- 品牌關懷與體驗邀請。

公開文案不得將 `GIFT` 稱為測試碼、試用碼或白老鼠名額。

## 共用兌換流程

`STAR` 與 `GIFT` 使用同一份兌換表單及同一套指南製作流程。收禮者提交有效且未使用的兌換碼後，取得相同的資料填寫、客服協助與指南交付服務。

兌換表單至少驗證：

1. 格式符合 `^(STAR|GIFT)-[0-9]{4}-[A-HJ-NP-Z2-9]{4}$`。
2. 完整代碼存在於兌換碼清單。
3. 代碼尚未兌換。
4. 成功受理後將代碼狀態改為已使用，避免重複兌換。

## 後台欄位

兌換碼清單至少保留：

- 完整兌換碼
- 發行類型：正式營運／品牌贈送
- 發行年份
- 建立日期
- 對應訂單或贈送註記
- 使用狀態
- 兌換日期
- 收件聯絡資料

`GIFT` 不需要虛構訂單編號；以贈送原因或對象註記即可。

## 網站呈現

網站可公開顯示兩種格式範例，但不公開有效兌換碼、兌換碼清單或兌換表單入口。相關文案統一描述為：

> 取得有效兌換碼後，即可進入專屬申請流程。

網站不得將兌換資格限定為只有付費購買者，因為正式購買後轉送與品牌贈送都同時存在。

## 驗收條件

- 公開網站不再使用舊格式 `STAR-XXXX-XXXX`。
- 正式營運範例符合 `STAR-YYYY-XXXX`。
- 品牌贈送範例符合 `GIFT-YYYY-XXXX`。
- 公開文案清楚涵蓋自用、顧客轉送及品牌贈送。
- 測試拒絕 `TEST-`、`PGG-` 與其他未核准前綴。
- `STAR` 與 `GIFT` 的服務內容及兌換入口相同。
