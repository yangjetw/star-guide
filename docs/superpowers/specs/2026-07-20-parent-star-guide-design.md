# 《親子成長指南》品牌網站設計規格

## 1. 專案目標

建置一個可部署至 GitHub Pages 的繁體中文一頁式網站，取代現有 Gamma 頁面。新站保留原有核心資訊，但重新整理文案、設計層級與銷售動線，以「星空療癒」建立「赫爾墨斯的小宇宙」的品牌記憶。

網站的首要成功指標是讓家長快速理解產品價值、找到合適方案，並透過官方 LINE 取得付款資訊。次要指標是讓已付款使用者容易找到付款回報表單。

## 2. 已確認的資料來源

- 現有品牌頁：`https://parent-star-guide-1tpyu0y.gamma.site/`
- 官方 LINE：`https://lin.ee/gMMpzNy`
- 付款完成回報單：`https://docs.google.com/forms/d/e/1FAIpQLSffcXc1FyJsZwo8qBXpAna4_lMZ_n04s4t9wWYlo5NSD1qxUQ/viewform`
- 指南申請／兌換表單：私人兌換表單（網址不寫入公開 repository）
- 現有 Google Sheet 與 Apps Script 的付款核對、兌換碼、Email 與指南處理流程

「feishu 的副本」試算表不是新網站流程的準據，不納入實作範圍。

## 3. 範圍

### 3.1 納入範圍

- 回應式一頁式品牌與銷售頁
- 星空療癒視覺系統
- 原站文案的精簡、潤飾與重新組織
- 三種方案與單位價格呈現
- 官方 LINE 與付款回報 Google 表單連結
- 常見問題、隱私與客製數位內容退費說明
- 桌機、平板與手機專屬排版
- 可存取性、載入效能與外部連結驗證

### 3.2 不納入範圍

- 新的購物車、線上金流或會員系統
- 新的資料庫或客製後台
- 在 GitHub Pages 直接收集 Email、姓名或出生資料
- 改寫現有 Google Forms、Google Sheet 與 Apps Script 核心流程
- 在公開網站顯示銀行帳號、街口支付或其他收款資訊
- 將指南申請／兌換 Google 表單作為公開首頁 CTA

## 4. 技術架構

網站採用純靜態架構：語意化 HTML、CSS 與少量原生 JavaScript。不使用前端框架，不建立後端，不新增執行期依賴。

- GitHub Pages 提供靜態檔案托管。
- Google Forms 處理付款回報與指南申請資料。
- Google Sheet 與 Apps Script 繼續處理人工核款、兌換碼生成、Email、兌換驗證、地理編碼、時區與指南製作資料。
- 網站不儲存個人資料，不設置追蹤型 Cookie，首版不加入第三方分析碼。

## 5. 使用者流程

### 5.1 購買流程

1. 訪客瀏覽產品價值、製作方式與三種方案。
2. 訪客點擊方案 CTA 後，開啟官方 LINE 以取得付款資訊。
3. 付款完成後，使用者從網站的「已完成付款？」次要入口開啟付款回報 Google 表單。
4. 管理者核對款項，透過現有 Apps Script 產生並寄出兌換連結。

### 5.2 兌換與指南申請流程

1. 收件者點擊 Email 中的現有 Apps Script 兌換連結。
2. Apps Script 顯示「你收到一份禮物」頁面。
3. 收件者點擊開啟禮物，進入已預填兌換碼的指南申請 Google 表單。
4. 表單送出後，現有 Apps Script 驗證兌換碼，處理出生資料並進入指南製作流程。

## 6. 頁面資訊架構

1. **固定導覽列**：品牌名稱、指南介紹、方案、常見問題、LINE CTA。
2. **Hero**：「每個孩子，都是一座獨特的宇宙。」、價值主張、介紹錨點與 LINE CTA。
3. **家長困擾**：情緒爆發、潛力未發揮、教養方式失效、內心想法成謎。
4. **指南價值**：個性與天賦、情緒與衝突、親子互動橋接。
5. **製作流程**：出生資料、星盤與關係節奏、兒童心理與生活情境、完成 PDF 指南。
6. **交付內容**：超過八千字 PDF、個人分析、情緒節點、實用情境、關係節奏圖像。
7. **方案與價格**：三張方案卡、每份單價、推薦與最優惠標籤、LINE CTA。
8. **家長見證**：保留現有三則見證，統一語氣與標點。
9. **常見問題**：出生時間誤差、資料用途、付款後流程、交付時間、客製數位內容退費規則。
10. **最終 CTA**：「懂，是比愛更深刻的慈悲。」、LINE CTA、已付款回報入口。
11. **Footer**：品牌名稱、版權、資料與退費說明錨點。

## 7. 方案呈現

- **自用方案**：1 份／NT$3,980，使用最顯眼視覺，標示「初次體驗推薦」。
- **好友分享包**：5 份／NT$18,900，每份 NT$3,780。
- **團購祝福組**：12 份／NT$39,800，每份約 NT$3,317，標示「最優惠」。

所有方案的主要按鈕都開啟官方 LINE，不在方案卡中顯示公開收款資訊。

## 8. 視覺系統

### 8.1 風格

整體採「星空療癒」：深藍、薰衣草紫與柔金形成宇宙氛圍，搭配奶油白與淺紫閱讀區塊。視覺元素以 CSS 漸層、星芒、軌道、光暈與圓角卡片為主，避免過多裝飾干擾文字。

核心色彩：

- 深空藍：`#101329`
- 深紫藍：`#1B1D3E`
- 薰衣草紫：`#DAD0F5`
- 柔金：`#EFCB7D`
- 奶油白：`#FBF4E6`
- 主要文字白：`#F8F4FF`
- 淺色背景主要文字：`#292843`

### 8.2 字體

- 大標、區塊標題與金句：`LXGW WenKai TC`
- 內文、導覽、按鈕與資料文字：`Noto Sans TC`
- 字體來源：Google Fonts
- 載入失敗備援：繁中系統楷體／明體與系統無襯線字體堆疊

### 8.3 字級與閱讀

- 桌機內文：19px，行高約 1.7
- 手機內文：18px，行高約 1.7
- Hero 大標：桌機約 54–72px，手機約 38–42px，使用 `clamp()` 平滑調整
- 區塊標題：桌機約 34–48px，手機約 29–34px
- 卡片標題：至少 18px
- 手機主要按鈕：字級至少 16px，高度至少 48px

## 9. 回應式與手機規格

- 主要斷點：768px。
- 768px 以下，所有多欄卡片改為單欄。
- 導覽列簡化為品牌錨點、選單與 LINE 入口。
- 手機底部提供不遮擋內容的固定主要 CTA。
- 桌機比較表不直接縮小，手機版改為垂直卡片或條列。
- 按鈕、連結與 FAQ 手風琴具有至少 44×44px 的觸控目標。
- 實作必須在 360px、390px、768px、1024px 與 1440px 寬度下驗證。

## 10. 互動行為

- 導覽錨點平滑滾動至對應區塊，並為「減少動態」使用者停用平滑動畫。
- FAQ 採語意化可展開元件，支援鍵盤操作。
- 外部連結清楚標示目的地，官方 LINE 與 Google 表單在新分頁開啟。
- 「已完成付款？」入口視覺層級低於主要 LINE CTA，但在方案區與頁尾都可找到。
- 動畫只用於淡入、星光微動與按鈕狀態；不使用視差滾動或大範圍持續動畫。

## 11. 隱私與業務說明

- GitHub Pages 不建立任何個人資料輸入欄位。
- 出生資料、Email、兌換碼與付款回報都由現有 Google Forms 處理。
- 網站說明出生資料只用於本次指南客製化，並連結至表單內的完整確認條款。
- 依現有 Google 表單內容，說明本商品為客製數位內容，一經付款並填寫資料即啟動製作，不接受取消或退費。
- 銀行與街口收款資訊只透過官方 LINE 提供，不出現在公開網站原始碼。

## 12. 錯誤處理與降級策略

- Google Fonts 失敗時改用本機系統字體，版面仍保持可讀。
- JavaScript 失敗時，頁面內容、LINE 連結與 Google 表單連結仍可使用。
- FAQ 以原生語意元件實作，不依賴 JavaScript 才能閱讀。
- 外部連結在發佈前逐一驗證；若 Google 表單無法開啟，使用者仍可透過官方 LINE 聯絡。
- 不將關鍵購買資訊放在只有動畫或圖像才看得到的位置。

## 13. 驗證與驗收條件

### 13.1 功能

- 導覽錨點、所有 LINE CTA 與付款回報表單連結正確。
- 三種方案的份數、總價與單價正確。
- 外部連結具有正確的安全屬性。
- 桌機導覽、手機選單、FAQ 與固定 CTA 行為正確。

### 13.2 回應式

- 360px 到 1440px 之間沒有水平滾動、文字截斷或按鈕遮擋。
- 手機版方案、見證與常見問題改為單欄，閱讀順序正確。
- 固定 CTA 不遮擋 Footer 與最後一個可操作元件。

### 13.3 可存取性

- 所有互動元件可使用鍵盤操作，有明顯焦點狀態。
- 標題層級、landmark、連結名稱與圖片替代文字完整。
- 主要文字與背景對比達 WCAG AA。
- 支援 `prefers-reduced-motion`，禁用非必要動畫。

### 13.4 效能與品質

- 關鍵首屏不依賴大型照片才能呈現。
- 字體只載入實際使用的字重，並使用 `font-display: swap` 對應的 Google Fonts 載入方式。
- 圖像使用適當尺寸、現代格式與延遲載入；首屏視覺優先用 CSS 建構。
- HTML 、CSS 與 JavaScript 無未處理錯誤，瀏覽器控制台沒有頁面本身造成的錯誤。

## 14. 實作邊界

首版以一個靜態站點完成，不把網站專案擴大為電商、會員系統或指南製作平台。若未來要自動金流、自動對帳或自建表單，必須作為獨立專案重新設計安全、資料與運維架構。
