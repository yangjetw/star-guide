# 赫爾墨斯的小宇宙：指南核心與品牌角色旅程設計

日期：2026-07-25  
網站：`https://yangjetw.github.io/star-guide/`

## 一、設計目標

將目前的靜態網站整理為一個完整、可信任且具有品牌歸屬感的網站，而不是只追求立即成交的一頁式銷售頁。

網站的第一任務仍是完整介紹《親子成長指南》，讓訪客依序理解：

1. 家長面對的問題。
2. 指南是什麼。
3. 指南如何製作。
4. 指南包含哪些分析與可實際使用的建議。
5. 需要提供哪些資料。
6. 指南與常見星盤解讀、線上諮詢、通用書籍及制式 PDF 的差異。
7. 真實家長的閱讀感受。
8. 如何購買、送禮、申請及取得協助。

品牌角色系統只負責延伸產品意義與後續參與路徑，不取代指南介紹。

## 二、品牌與角色定義

對外統一使用：

> 赫爾墨斯的小宇宙，由星學會運營。

法律與客服資訊：

- 營運主體：星學會有限公司。
- 統一編號：69708677。
- 客服信箱：`astrokidsguide@gmail.com`。
- 官方 LINE：`https://lin.ee/gMMpzNy`。

角色定義如下：

### 點星者

購買指南作為禮物、促成一個家庭開始理解孩子的人。點星者不等同於實際使用指南照顧孩子的人。

核心文案方向：

> 你送出的不只是一份指南，而是為一個家庭點亮理解的起點。

### 領航者

實際擁有並使用指南、負責陪伴與引領自己孩子的父母或主要照顧者。

指南是領航者理解孩子的地圖，不代替父母作決定，也不把孩子定型。

### 導航者

願意培養更多方法、能力與責任，協助多位領航者及更多家庭的人。

核心文案方向：

> 陪伴一個孩子，需要理解；陪伴更多家庭，更需要方法、能力與責任。

在課程內容、資格與制度尚未正式確定前，網站不得宣稱認證、保證就業、專業執照或確定收入。

## 三、採用的內容架構

採用「指南核心＋角色旅程」架構。

訪客的主要理解順序為：

```text
看見孩子的獨特
→ 理解《親子成長指南》的價值
→ 透過內容、成品與家長心聲建立信任
→ 選擇為自己購買或送給重要的家庭
→ 成為領航者或點星者
→ 有意承擔更多責任者進一步了解導航者計畫
```

不採用以下兩種極端：

- 純商品銷售架構：雖然直接，但容易形成廉價促銷頁的觀感。
- 純品牌故事架構：雖然具有氛圍，但可能使指南內容、價格及行動入口不清楚。

## 四、頁面資訊架構

### 1. `index.html`：指南介紹首頁

首頁是全站內容核心，保留原有指南文字、AI 圖片與真實回饋截圖，重新整理層級及版面。

建議段落順序：

1. 星空主視覺與核心承諾。
2. 家長常見的困惑與情境。
3. 《親子成長指南》是什麼。
4. 每個孩子都是獨特的：指南的三項主要價值。
5. 指南如何製作：出生資料、占星分析、兒童心理學及生活情境的整合。
6. 申請所需資料及必要條件。
7. 實際交付內容、指南畫面與使用方式。
8. 與其他常見服務的差異及價格價值。
9. 指南可能為親子關係帶來的改變。
10. 家長真實心聲截圖。
11. 購買／送禮行動入口。
12. 品牌角色旅程：點星者、領航者、導航者。
13. 品牌收束及客服入口。

首頁不得因加入角色系統而縮短指南說明。重複的說法可以合併，但每個原有重點必須有明確位置。

### 2. `gift.html`：點星者送禮頁

本頁服務想送出指南的人，主要回答：

- 為什麼這份禮物具有意義。
- 適合送給什麼樣的家庭。
- 每個方案包含什麼。
- 購買者與收禮者各自需要做什麼。
- 收禮者如何取得客製指南。
- 如何取得客服協助。

顧客可理解的流程：

1. 選擇合適的送禮方案。
2. 向官方 LINE 洽詢並完成購買。
3. 購買者取得可轉送的電子禮物資訊。
4. 收禮的父母依指引提供製作指南所需資料。
5. 完成客製指南後交付給收禮者。

頁面不得公開：

- `STAR`、`GIFT` 或其他兌換碼前綴。
- 品牌主動贈送、朋友試用等營運分類。
- 內部編碼格式、人工分檔方式及共用兌換規則。
- 只有營運人員才需要知道的例外處理。

上述規則可以保留在私人營運文件及內部測試中，但不得出現在公開 HTML、SEO 描述或公開 FAQ。

### 3. `navigator.html`：導航者計畫

導航者是重要品牌角色，保留在主導航列，不移至頁尾或弱化為次要連結。

本頁內容順序：

1. 導航者的使命及影響力。
2. 領航者與導航者的差異。
3. 為什麼協助更多家庭需要更多方法、能力與責任。
4. 適合加入的人。
5. 預計培養的理解、溝通與陪伴能力。
6. 角色邊界：不代替家長決定、不對孩子貼標籤。
7. 申請方式。

主要行動按鈕直接連至既有 Google 表單：

`https://forms.gle/GsUYYrCTFfHkA6RE8`

官方 LINE 作為有疑問時的次要入口。

### 4. `refund.html`：安心購買與服務說明

本頁不再描述內部營運，而是集中建立購買信任，包含：

1. 品牌、營運公司及客服資訊。
2. 購買、付款與交付流程。
3. 客製服務開始前後的處理原則。
4. 資料用途、保存與刪除原則。
5. 兌換或交付發生問題時的處理方式。
6. 退款與聯絡方式。

公開文字應以顧客能採取什麼行動為中心，不使用內部代碼、員工作業術語或品牌贈送分類。

## 五、視覺與版面系統

整體延續使用者喜歡的星夜封面，不照抄 Gamma，也不把所有內頁做成相同卡片堆疊。

視覺方向：

- 主色：深星藍。
- 背景：溫暖奶油白。
- 強調色：柔和橘金。
- 輔助色：低飽和珊瑚橘與暖灰。
- 避免大面積冷綠、低對比文字及廉價漸層按鈕。
- AI 圖片保留原有敘事意義，可調整裁切、顯示比例與所在段落。
- 真實家長回饋保留截圖形式，以提供可辨識的真實感，不改寫成假造的姓名或評分。

版面原則：

- 每一個內容段落只傳達一個主要訊息。
- 圖片與文字必須有敘事關係，不以固定左右各半版型套用全部內容。
- 桌面版內文不小於約 18px，重要說明約 20px；手機版內文不得小於 16px。
- 標題、內文、補充文字需有穩定且可預期的層級。
- 導航列必須一眼可辨識，並清楚標示目前所在頁面。
- 行動按鈕文案使用具體動作，例如「了解送禮方案」「填寫導航者申請表」。
- 手機寬度 375px 起不得出現橫向捲動、文字截斷或圖片遮蔽。
- 所有互動元件保留清楚的鍵盤焦點與至少 44×44px 的點擊範圍。
- 所有一般文字與背景的對比至少符合 WCAG AA。

動效維持克制，只允許不影響閱讀的淡入或位移；必須支援 `prefers-reduced-motion`。靜態內容不得依賴 JavaScript 才能閱讀。

## 六、轉換與信任設計

全站不以密集催購製造壓力，而以「理解、證據、透明、行動」建立購買信心：

1. 理解：先說出父母正在面對的真實問題。
2. 證據：展示指南成品、製作方式與真實回饋。
3. 透明：說清楚需要的資料、交付內容、價格與服務原則。
4. 行動：在完成一段理解後提供相應入口，不讓每一屏都重複催購。

各頁主要行動：

- 首頁：了解指南／了解送禮方案。
- 送禮頁：洽詢購買。
- 導航者頁：填寫導航者申請表。
- 服務說明頁：聯絡客服。

## 七、公開與內部資訊邊界

公開網站只呈現顧客需要知道、且能增加理解與信任的內容。

內部資訊包括但不限於：

- 兌換碼前綴及格式。
- 付費、品牌贈送及朋友體驗的分類方式。
- 人工分檔及核對方法。
- 私人兌換表單網址。
- 內部研究編號與營運欄位。

公開頁可以描述「購買後會收到申請指引」及「持有效資格者可申請指南」，但不能揭露上述內部實作。

導航者申請表屬於刻意公開的加入入口，不視為私人兌換表單。

## 八、技術結構

維持 GitHub Pages 可直接發布的靜態 HTML/CSS 架構，不新增後端、資料庫或高維護成本框架。

建議整理方向：

- 四頁共用一致的 header、nav、footer 與設計變數。
- HTML 使用語意化的 `header`、`nav`、`main`、`section`、`article`、`figure` 及正確標題層級。
- 移除重複或已停用的 CSS 規則。
- 依功能整理樣式：全域設計變數、共用版面、共用元件、各頁小範圍覆寫、響應式規則。
- 圖片保留明確尺寸，使用合適的 `loading`、`decoding`、`srcset` 與 `sizes`，避免版面位移及手機下載過大圖片。
- 外部連結使用安全的 `rel` 屬性。

## 九、錯誤與例外處理

- 公開連結若尚未準備完成，不顯示虛假的「立即付款」或「立即兌換」按鈕。
- 購買服務尚以 LINE 人工處理時，按鈕必須明確寫為「洽詢購買」，不得讓顧客誤以為已進入線上結帳。
- 不承諾尚未確定的製作天數、名額、認證、保證效果或退款條件。
- 指南內容不得描述為醫療、心理治療、診斷或保證改變孩子。
- 若出生時間不符合申請條件，公開文字應在購買前清楚提醒，避免收禮後才發現無法製作。

## 十、驗收與測試

自動化測試至少涵蓋：

- 四個公開頁面可正常解析且只有一個 `h1`。
- 標題層級連續，主要導覽與頁尾資訊一致。
- 公開頁不包含 `STAR-`、`GIFT-`、品牌贈送及內部兌換流程文字。
- 導航者 Google 表單只出現在允許公開的加入入口。
- 私人指南兌換表單不出現在公開 HTML。
- 公司名稱、統一編號、客服信箱及官方 LINE 正確。
- 圖片具有尺寸及替代文字。
- 所有外部新分頁連結具有安全屬性。
- 手機 375px、平板 768px、桌面 1024px 與 1440px 均無橫向捲動或截斷。

人工視覺驗收至少檢查：

- 首頁仍能完整理解指南，不會被角色名稱搶走主題。
- 導航列一眼可見。
- 桌面與手機內文皆可舒適閱讀。
- 圖片與文字有明確承接關係。
- 家長回饋截圖清楚可辨識。
- 四頁具有同一品牌感，但不呈現機械式重複版型。
- 送禮頁讓人想送、導航者頁讓合適的人想加入、服務說明頁讓人放心購買。

## 十一、完成標準

當訪客瀏覽完成後，應能清楚回答：

1. 《親子成長指南》為何存在、如何製作及包含什麼。
2. 這份指南與一般星盤或通用教養內容有何不同。
3. 購買前需要準備什麼，購買後會如何取得服務。
4. 自己可以成為領航者、點星者，或進一步了解導航者計畫。
5. 赫爾墨斯的小宇宙由哪個法律主體運營，以及如何取得協助。

網站的最終感受應是溫暖、專業、可信任且值得加入，而不是廉價、鬆散或只想促成一次交易。
