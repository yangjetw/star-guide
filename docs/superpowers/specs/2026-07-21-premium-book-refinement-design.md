# 「精品書冊」版面精緻化設計規格

日期：2026-07-21  
專案：赫爾墨斯的小宇宙／親子成長指南  
正式網站：https://yangjetw.github.io/star-guide/

## 1. 目標

在不更動既有文案、內容順序、價格、圖片與轉換流程的前提下，將目前較為分散的長頁式版面升級為集中、連續、溫暖的「精品書冊」閱讀體驗。

成功的畫面應具備以下特徵：

- 桌機版的內容聚合在一個明確的中央閱讀舞台，不再向左右散開。
- 各區塊看起來屬於同一本書，而不是一系列彼此無關的卡片。
- 視線可以由封面、章節、價格、見證一路自然移動到最終行動按鈕。
- 手機版維持大字、單欄與舒適觸控，不為了裝飾犧牲閱讀性。
- 整體仍保留原 Gamma 的溫馨星空意象與家長可親近感。

## 2. 不變的產品內容

以下內容不在本次改版範圍內：

- 所有可見文案與區塊順序。
- `NT$3980` 價格與單一方案定位。
- 現有八張本機 WebP 圖片及其替代文字。
- 官方 LINE 連結：`https://lin.ee/gMMpzNy`。
- 付款完成回報表單連結。
- 私密兌換表單不得出現在公開產物中的限制。
- 純靜態 GitHub Pages 架構，不加入後端、登入、購物車或執行期 JavaScript。

## 3. 選定方向：B「精品書冊」

### 3.1 中央閱讀舞台

- 頁面外層使用低對比暖米色背景，提供安靜邊界。
- 主要內容收進最大寬度約 `1080px` 的暖白書頁容器。
- 書頁在桌機版使用柔和圓角與低透明度陰影，建立完整而連續的物件感。
- 手機版移除不必要的外框感，書頁貼近螢幕但保留至少 `16px` 左右安全留白。
- 原本分散的全寬區段改在同一內容軸上排布，章節之間縮短空白但保留清楚呼吸。

### 3.2 封面式首屏

- Hero 成為書冊封面，而不是單純左右兩欄。
- 星空親子圖作為主要情緒畫面；桌機版可在保留主體的前提下使用深色漸層覆蓋，使標題與按鈕集中在同一視線區。
- 手機版避免在複雜圖像上直接壓長文；可改為圖片在上、文字在下的同一封面卡結構。
- 首屏只突出一個主要動作「《親子成長指南》是什麼？」；LINE 作為次要動作，維持原有連結。

### 3.3 章節導讀系統

- 主要故事區段依原順序加入視覺章節編號 `01–07`，編號僅作裝飾與導讀，不改變標題文字。
- 區段之間使用小型星點、細線或留白節奏連接，形成一本書往下翻閱的感覺。
- 桌機版保留圖片與文字左右交錯，但統一進入同一種章節卡片骨架：一致內距、一致圓角、一致圖片邊界。
- 章節卡不全部使用實體框線；以背景色階、留白與局部陰影分層，避免再次產生卡片碎片感。
- 圖片比例依各資產的自然比例設計，既有不裁切要求繼續有效。

### 3.4 視覺層級與字體

- 大標與章節標題使用柔和的繁體中文襯線／宋體字族：`"Noto Serif TC", "Songti TC", "PMingLiU", serif`。
- 內文、按鈕、標籤保留清楚的無襯線字族：`"Noto Sans TC", "PingFang TC", "Microsoft JhengHei", sans-serif`。
- 不新增外部字型下載，確保 GitHub Pages 載入穩定；使用者裝置有對應字型時自然套用。
- 內文基準維持至少 `18px`；手機版不縮小閱讀字級。
- 標題行寬受到限制，避免橫向鋪滿造成視線鬆散。

### 3.5 色彩與材質

- 外層背景：暖米白，與中央書頁形成低對比邊界。
- 書頁背景：接近白色的暖白。
- 主文字：近黑深夜藍，取代生硬純黑。
- 主 CTA：保留蜜桃橘；LINE CTA：保留品牌綠。
- 裝飾色：低飽和杏桃、星光金與霧藍，只用於章節編號、星點及淡背景。
- 陰影柔和且一致；禁止厚重玻璃感、霓虹外光與過多浮動卡片。

## 4. 重要區段設計

### 價格區

- 價格區作為整頁中段的主要視覺錨點。
- 在中央書頁內建立較深或較暖的完整價格面板，讓 `NT$3980`、說明與付款回報按鈕形成單一群組。
- 不新增方案、不加入折扣倒數或虛假稀缺訊息。

### 比較表

- 維持現有完整內容與表格語意。
- 桌機版置於中央書頁的寬版章節中，表頭與本方案列使用品牌色階建立焦點。
- 手機版維持容器內橫向捲動，不允許整頁橫向溢位。

### 家長見證

- 改為同一章節中的精緻引言卡組，統一引號、署名與間距。
- 桌機版可用三欄，但卡片必須共用同一底板或視覺軌道，避免各自漂浮。
- 手機版依序堆疊，保持完整文字與清楚署名。

### 結尾行動區

- 保留完整星空家庭圖，繼續遵守自然比例不裁切規則。
- 圖片、結語與兩個外部 CTA 收進同一個結尾封底區。
- 主要付款回報與次要 LINE 動作保持清楚區分，但兩者均不得低於 `48px` 觸控高度。

## 5. 響應式行為

### 桌機（`>= 1024px`）

- 顯示完整中央書頁、封面疊字與交錯章節。
- 圖文欄寬以文字可讀性為優先，不讓文字欄過寬。

### 平板（`769–1023px`）

- 書頁縮窄，部分圖文仍可維持雙欄；空間不足的章節提前轉為單欄。
- 所有按鈕與表格維持完整可操作。

### 手機（`<= 768px`）

- 全部故事章節改為單欄，維持原先經驗中「文字先、圖片後」的內容理解順序；封面例外可採圖片在上、文字在下。
- 圖片、文字、章節編號留在同一章節容器內，不產生視覺斷裂。
- 內文至少 `18px`，按鈕至少 `48px` 高，頁面不得出現橫向溢位。

## 6. 動態與無障礙

- 不加入執行期 JavaScript 或滾動動畫套件。
- 僅使用 CSS 提供輕微按鈕上移、陰影變化與連結回饋。
- `prefers-reduced-motion` 下取消非必要過渡。
- 保留現有語意章節、跳至主要內容連結、焦點樣式、表格 `scope` 與圖片替代文字。
- 色彩對比需滿足一般文字可讀性；裝飾星點不得承載唯一資訊。

## 7. 實作邊界

- 主要修改範圍為 `index.html`、`styles.css` 與對應測試。
- HTML 可增加不影響可見文案的結構容器、章節編號及裝飾元素。
- 不更換圖片、不重寫文案、不增加新外部服務。
- GitHub Pages 工作流程保持原樣，完成後直接部署到既有正式網址。

## 8. 驗收標準

- 原有 11 個內容區段、完整文案、價格與外部連結均保持不變。
- 桌機版可清楚辨識單一中央書頁與連續章節軸。
- 主要故事區具一致的章節編號、內距與圖片處理。
- `360px`、`390px`、`768px`、`1024px`、`1440px` 均無整頁橫向溢位。
- 手機內文字級至少 `18px`，主要觸控目標至少 `48px`。
- 八張本機 WebP 圖片均能載入且不發生不合理主體裁切。
- 比較表的橫向捲動限制在自身容器。
- LINE 與付款回報表單連結正確；私密兌換表單 ID 不存在於公開 HTML/CSS。
- 鍵盤焦點、減少動態偏好與表格語意繼續有效。
- 自動化測試與正式網址的瀏覽器驗證全部通過後才視為完成。
